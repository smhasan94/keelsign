# Fuzzing

The image parser of `keelsign-verify` (`keelsign_verify::image`) is fuzzed with
[cargo-fuzz](https://github.com/rust-fuzz/cargo-fuzz) and libFuzzer (SHA-39). One target,
`parse_image`, covers the parser (`Image::parse`, `Image::read_from` over a byte slice,
`Header`/`RawHeader`/`TlvInfo::parse`) and the TLV iterator (`Image::tlvs`,
`TlvArea::iter`/`pairs`, `Tlv::kind`).

The target is differential: `keelsign_fuzz::check_parse_image` runs the parser and an
independent reference parser (`fuzz/src/oracle.rs`, a copy of the SHA-35 test oracle in
`keelsign-verify/src/image.rs`) on every input and panics, which libFuzzer reports as a
crash, when they disagree or when a parsed image breaks an invariant (TLVs in bounds and
tiling their areas, header and area bytes equal to the input's, `read_from` following its
contract with a full and a 4 KiB TLV buffer). The parser never panics on its own (it reads
only through checked slicing), so without the reference parser a fuzzer could not find a
parser that silently accepts a bad image; with it, it can (see TP1 below).

## Prerequisites

- A nightly toolchain (cargo fuzz uses sanitizers and `-Z` flags). CI pins
  `nightly-2026-09-29` (in `.github/workflows/fuzz.yml`; bump the two together); locally
  any recent `nightly` works:

  ```sh
  rustup toolchain install nightly
  ```

- cargo-fuzz 0.13.2, the release CI installs:

  ```sh
  cargo install cargo-fuzz --version 0.13.2 --locked
  ```

- For coverage only, the LLVM tools of that nightly:

  ```sh
  rustup component add llvm-tools-preview --toolchain nightly
  ```

- `python3` for the corpus generator and the coverage check (standard library only).

`scripts/fuzz.sh` uses `cargo +$FUZZ_TOOLCHAIN fuzz` with `FUZZ_TOOLCHAIN` defaulting to
`nightly`; CI sets it to the pin.

## Layout

| Path | What |
|---|---|
| `fuzz/Cargo.toml`, `fuzz/Cargo.lock` | The `keelsign-fuzz` crate: a standalone workspace (not a member of the root one), `publish = false`, `keelsign-verify` by path with no features, `libfuzzer-sys = "=0.4.13"`, `unsafe_code = "forbid"` |
| `fuzz/fuzz_targets/parse_image.rs` | The target: `fuzz_target!(\|data\| keelsign_fuzz::check_parse_image(data))` |
| `fuzz/src/lib.rs` | `check_parse_image` and the `cov` arms (one per TLV kind and error variant, each marked `// cov:`), plus the stable tests |
| `fuzz/src/oracle.rs` | The reference parser |
| `fuzz/corpus/parse_image/` | The committed seed corpus (script output) |
| `fuzz/corpus/MANIFEST.json` | Every seed's source, sha256, size and expected results |
| `fuzz/tp1-tlv-length-off-by-one.patch` | The bug TP1 injects into a copy of the parser |
| `scripts/fuzz.sh` | `smoke`, `nightly`, `run SECS`, `summary`, `tp1`, `coverage` |
| `scripts/fuzz_coverage_check.py` | The TP2 check of a coverage report |
| `scripts/gen_fuzz_corpus.py` | The corpus generator |

Gitignored (`fuzz/.gitignore`): `fuzz/target/`, `fuzz/corpus-work/` (inputs the fuzzer
finds), `fuzz/artifacts/` (crashes, logs, summary), `fuzz/coverage/`,
`fuzz/fuzz-artifacts.tar.gz`, and anything in `fuzz/corpus/parse_image/` other than the
committed `fixture-*.bin` and `synth-*.bin`.

The library and its tests build on stable, so the checks also run as ordinary tests:

```sh
cargo test --manifest-path fuzz/Cargo.toml --locked
```

## Corpus

`fuzz/corpus/parse_image/` is generated by `scripts/gen_fuzz_corpus.py` (offline; never
edit it by hand):

- `fixture-*.bin`: every image under `tests/fixtures/images/` (52), except
  `mcuboot-ed25519-200k.bin` (205 KB, over `-max_len=8192`; otherwise the layout of
  `mcuboot-ed25519.bin`) and `policy-matrix.bin` (an index, not an image).
- `synth-*.bin` (11): one image with a TLV of every `TlvKind`, one per `ParseError`
  variant, one valid image whose TLV areas (4,244 bytes) exceed the 4 KiB `read_from`
  buffer (`Error::TlvAreaTooLarge`), and one with empty TLV areas.

63 seeds, 220 KB, the largest 8,192 bytes; not minimised. `fuzz/corpus/MANIFEST.json`
records `expect_parse` (`Image::parse`) and `expect_read_from_4k` (`Image::read_from` with
a 4096-byte buffer) for each; `keelsign_fuzz::tests::every_seed_matches_its_manifest_expectations`
checks them, and `keelsign_fuzz::tests::committed_corpus_reaches_every_tlv_kind_and_error_variant`
checks that the corpus reaches every `cov` arm. Rerun the generator (or
`scripts/make-fixtures.sh`, [fixtures.md](fixtures.md)) when an image fixture changes:

```sh
python3 scripts/gen_fuzz_corpus.py           # rewrite the seeds and MANIFEST.json
python3 scripts/gen_fuzz_corpus.py --check   # verify, writes nothing
```

The fuzzer reads the committed seeds but writes what it finds to `fuzz/corpus-work/`
(the first corpus directory), so the committed corpus never changes during a run.

## Running

```sh
scripts/fuzz.sh smoke        # 120 s, as the PR job
scripts/fuzz.sh nightly      # 1800 s, as the nightly job (FUZZ_SECONDS overrides both)
scripts/fuzz.sh run 600      # any number of seconds
scripts/fuzz.sh summary      # fuzz/artifacts/summary.txt and fuzz/fuzz-artifacts.tar.gz
```

Each run fetches with `--locked` first (cargo fuzz has no `--locked`), then runs

```sh
cargo +$FUZZ_TOOLCHAIN fuzz run parse_image fuzz/corpus-work/parse_image fuzz/corpus/parse_image -- \
    -max_total_time=SECS -timeout=10 -max_len=8192 -print_final_stats=1
```

and logs to `fuzz/artifacts/run.log`. A crash stops the run with a non-zero exit and
leaves the input in `fuzz/artifacts/parse_image/`.

## Ten-minute local run (AC1)

```sh
cargo +nightly fuzz run parse_image -- -max_total_time=600 -timeout=10 -max_len=8192 -print_final_stats=1
```

(from the repository root). It writes the inputs it finds into `fuzz/corpus/parse_image/`
under 40-hex-digit names; they are gitignored, and `gen_fuzz_corpus.py --check` and the
repo-checks ignore them. Or, keeping new inputs out of that directory and logging the run,
`scripts/fuzz.sh run 600`. It passes when it ends with `Done N runs in 600 second(s)` (libFuzzer
may print 601),
exits 0, reports `stat::slowest_unit_time_sec: 0` (no input near the 10 s timeout) and
`fuzz/artifacts/parse_image/` stays empty.

Recorded on an Apple M-series laptop (aarch64-apple-darwin, `nightly-2026-09-29`,
cargo-fuzz 0.13.2) with `scripts/fuzz.sh run 600`: `Done 22540546 runs in 601 second(s)`,
37,505 executions per second, `slowest_unit_time_sec: 0`, peak RSS 180 MB, no crash, exit 0
(SHA-39).

## Injected off-by-one (TP1)

```sh
scripts/fuzz.sh tp1
```

copies the committed tree (`git archive HEAD`, so commit first) to a temporary directory,
applies `fuzz/tp1-tlv-length-off-by-one.patch` there (the TLV length check in `split_tlv`
accepts a value that runs one byte past its area), and fuzzes that copy for up to 120 s
from the committed corpus. It passes (exit 0) only when the fuzzer crashes with the
harness's `Image::parse disagrees with the reference parser` within 120 s, and prints the
time and the number of executions it took. The patched parser does not panic (it returns
the value one byte short); only the reference parser notices. The repo-check
`repo_checks::fuzz::tp1_patch_applies_to_the_parser` fails when the patch no longer
applies (for example after an edit near `split_tlv`); regenerate it with `git diff` from
an edited scratch copy.

Recorded locally (SHA-39): found in 0–1 s (4,870 and 39,346 executions), once as the
parser accepting an image the reference parser rejects with `LengthMismatch`, once as a
different error from the same overrun.

## Coverage (TP2)

```sh
scripts/fuzz.sh coverage
```

runs `cargo fuzz coverage parse_image fuzz/corpus/parse_image` (the committed corpus, so
the result is deterministic), writes `llvm-cov` text and HTML reports to
`fuzz/coverage/parse_image/` (`coverage.txt`, `report.txt`, `html/`; never committed),
and runs `scripts/fuzz_coverage_check.py` on the text report. The check requires an
execution count above zero on the arms of `TlvKind::of` in `keelsign-verify/src/image.rs`
(every TLV-type branch) and on every `// cov:` line of
`fuzz/src/lib.rs` (29: the 19 TLV kinds, the 8 `ParseError` variants, and
`Error::Parse` and `Error::TlvAreaTooLarge` from `Image::read_from`). Of the 19
`TlvKind::of` arms, 18 lines are checked directly. The `KeelsignReserved` arm shares its
line with its `KEELSIGN_TLV_RANGE.contains(&t)` guard, which runs for every type that
reaches it, so that line's count can never be 0; the arm is checked through its
`// cov: TlvKind::KeelsignReserved` marker instead, and the checker's output says so.
`Error::Read`
cannot occur with a byte-slice reader (`image::tests::read_from_failure_at_every_call_is_read_error`
covers it); the other `Error` variants belong to `verify`, which this target does not
fuzz. `python3 scripts/fuzz_coverage_check.py --self-test` tests the checker itself.

Recorded locally (SHA-39): `fuzz coverage: 18 TlvKind::of arm lines reached directly, the
KeelsignReserved arm (shares its guard's line) through its marker, and all 29 cov markers
reached`.

## CI jobs (AC2, TP3)

`.github/workflows/fuzz.yml` (separate from `ci.yml`), on `nightly-2026-09-29` with
cargo-fuzz 0.13.2 (`taiki-e/cache-cargo-install-action`):

| Job | When | What |
|---|---|---|
| `fuzz-check` | every PR, nightly, manual | stable: `cargo fmt`, `cargo clippy -D warnings` and `cargo test` of the fuzz crate, `gen_fuzz_corpus.py --check`, `fuzz_coverage_check.py --self-test` |
| `fuzz-smoke` | every PR | `scripts/fuzz.sh smoke` (120 s); on failure uploads the contents of `fuzz/artifacts/` as `fuzz-smoke-<run id>` |
| `fuzz-nightly` | `cron: "17 3 * * *"` and `workflow_dispatch` | `scripts/fuzz.sh nightly` (1800 s, `timeout-minutes: 60`); always `scripts/fuzz.sh summary` and uploads `fuzz-nightly-<run id>` (30 days); then `scripts/fuzz.sh tp1` and `scripts/fuzz.sh coverage`, uploading the coverage report |

The nightly artifact holds `summary.txt` (toolchain, cargo-fuzz version, seconds, the
`Done` line, `crash_files=N` with the file names, libFuzzer's `stat::` lines) and
`fuzz-artifacts.tar.gz`, a tarball of `fuzz/artifacts/` that keeps the crash directory
`artifacts/parse_image/` even when it is empty (`upload-artifact` drops empty
directories). A healthy night shows `crash_files=0` and an empty `artifacts/parse_image/`
in `tar tzf fuzz-artifacts.tar.gz`. Scheduled runs happen only on the default branch
(after merge) and GitHub pauses them after 60 days without repository activity; a manual
dispatch runs the same job.

The same can be simulated locally:

```sh
FUZZ_SECONDS=60 scripts/fuzz.sh nightly && scripts/fuzz.sh summary && tar tzf fuzz/fuzz-artifacts.tar.gz
```

## Reproducing a crash

Download the failing run's artifact and unpack it outside the repository, for example in
`/tmp/keelsign-crash`. The two artifacts are laid out differently:

- `fuzz-nightly-<run id>` holds `summary.txt` and `fuzz-artifacts.tar.gz`; the tarball
  unpacks to `artifacts/parse_image/crash-<hash>`:

  ```sh
  cd /tmp/keelsign-crash && tar xzf fuzz-artifacts.tar.gz   # -> artifacts/parse_image/crash-<hash>
  ```

- `fuzz-smoke-<run id>` holds the contents of `fuzz/artifacts/` directly (no tarball):
  `run.log` and `parse_image/crash-<hash>`.

Then run the target on the crashing input from the repository root (cargo fuzz looks for
`fuzz/` in the current directory), giving the path to the unpacked file; it panics with
the disagreement or invariant that failed:

```sh
cargo +nightly fuzz run parse_image /tmp/keelsign-crash/artifacts/parse_image/crash-<hash>   # nightly
cargo +nightly fuzz run parse_image /tmp/keelsign-crash/parse_image/crash-<hash>             # smoke
```

Minimise it with `cargo +nightly fuzz tmin parse_image <path to crash-<hash>>` (also from the
repository root), turn it into a unit test of the parser in `keelsign-verify/src/image.rs`, and fix the
parser (or, if the reference parser is wrong, both oracles: `fuzz/src/oracle.rs` and
the test oracle in `image.rs`).
